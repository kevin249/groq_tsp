# 初始版本验证说明

## 运行方式

在仓库根目录执行：

```powershell
npm.cmd --prefix tools run pack
npm.cmd --prefix tools run check
```

检查脚本只使用 Node.js 内置模块，不需要安装 Mermaid 或 Playwright。只有重新生成硬件图形时才需要先安装 `tools` 中锁定的开发依赖。Linux / macOS 将命令中的 `npm.cmd` 替换为 `npm`。

单独核对资料引用可执行 `npm.cmd --prefix tools run check:references`。该检查同时核对源码、独立 HTML 和说明文档，要求外部资料使用公开 HTTP(S) 链接，并检查仓库内部文档导航是否存在。

## 自动化覆盖

| 检查脚本 | 组数 | 主要覆盖 |
| --- | --- | --- |
| `check-performance.cjs` | 15 | 算子 FLOPs、读写量、数值链、KV、容量、TTFT / TPOT、打包一致性 |
| `check-cluster.cjs` | 11 | 四种部署、头与通道分片、GQA 复制、环形归约、传输状态、带宽与容量 |
| `check-operators.cjs` | 8 | 六类 30 个操作、MAC / VXM / MEM 归属、小数值与重排守恒 |
| `check-playback.cjs` | 9 | 初始化、逐帧推进、暂停、继续、重播、连续播放与课堂切换 |
| `check-workspace.cjs` | 5 | 芯片与总览镜头、传输跟随、双流标签、详情面板和三栏结构 |
| `check-cycle.cjs` | 12 | 810 组静态计划、物理 ICU 冲突、SG 字节流、逐拍状态、回退和重放 |
| `check-request.cjs` | 11 | 八环节 42 操作、Prefill / Decode、跨段循环、完整播放和下一轮输入 |
| `check-references.cjs` | 4 | 网上资料引用、文档导航、内嵌脚本语法、独立 HTML 的离线运行资源 |
| 合计 | **75** | 当前初始版本的检查集合 |

共享界面替身和播放测试工具由 `check-playback.cjs` 提供。它们执行真实模型、应用脚本和动画时钟，使用程序构造的界面节点及绘图适配器接收结果。

## 报告与仓库约定

七类功能检查将中文 UTF-8 报告写入 `reports/`：性能计算、多芯片通信、算子与硬件、动画播放、界面与镜头、逐周期执行、完整请求流程。引用检查直接在控制台输出结果。

`reports/` 已加入忽略规则，不提交自动生成的检查记录。报告采用功能名称，检查过程不会重新在仓库根目录生成“第几版”文档。仓库长期维护 `README.md` 和 `docs/` 中的教学方案、设计说明、验证说明三份文档。

提交前应重新打包并运行全部检查，确认独立 HTML 与 23 个源脚本、7 份样式一致，并检查待提交内容中没有依赖目录、临时报告或旧版网页。

## 初始版本验证范围

初始版本包含三个课堂的运行代码、Mermaid 图形和参数化计算模型。发布检查以当前源文件及重新生成的独立 HTML 为对象，检查报告统一输出到忽略目录。

自动化检查不包含教学网页的浏览器点击、截图或视觉验收，也未连接真实 Groq 硬件。逐周期验证支持教学模型内部的整数时序一致性；参数化性能结果不属于设备实测。

资料链接的形式检查不请求网络。公开原文的访问记录及出版站点的验证限制见仓库说明中的公开资料表；不把网络状态当作动画功能测试结果。
