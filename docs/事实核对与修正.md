# GPU / Groq 事实核对与修正

核对日期：2026-09-09。以下只说明本仓库可视化依据，不代表 Qwen 已在 Groq 3 上完成编译部署。

## 本次发现与修正

1. 原默认流程略过 Prefill 后首个 Token，又将后续层折叠为一步。现在按 Prefill 全部层、首个 Token、Decode 全部层、下一 Token 顺序构造流程。每层各有自己的往返依赖，逐层可选择查看。
2. 原传输展示直接采用 BF16、int32 ID、单条 C2C 及固定 TP / EP。配置 dtype 不等于线上 dtype；这些假设不能产生已知的网络流量或实际耗时。默认不指定分片和专家编号；显式选择假设分片才显示示例。
3. 物理图补齐 GPU 侧 CX-9 和 Spectrum-X。LPX 前面板 Ethernet 与 C2C 光连接分开标识；托盘 Host CPU 不被强制串入每一次张量传输。Fabric 与 LPU 之间仅表示公开的功能关系，不声称知道 PCIe / DMA / 引脚布线。
4. 网络传输的外部、机架、托盘画面是同一交接的不同尺度，不能重复累计流量或时间。
5. 原权重占用标为“本次读取”，并由整片峰值计算纳秒，容易成为伪精确延迟。现在权重占用、张量占用、线上传输与实机时间分开；未公开时间显示“未公开”。FP8 是用户显式选择的假设，默认按配置 BF16 显示占用。
6. Flash-Next 参考实现 norm_topk_prob=True，Top-10 后需再归一化；合并系数为 α，而非原始全专家 softmax 概率。共享专家由独立 sigmoid 门控参与。
7. DeltaNet 递推补上查询除以 √128。FP32 状态矩阵占用只含递推状态；卷积历史另计，不能当作全部 Cache 或总访存量。
8. QSA 展开独立 Q 归一化 / RoPE、四 Token raw-K 均值、K 归一化 / 块位置 RoPE、四头 ReLU 分数聚合、选块与尾部保留。
9. 27B 配置 output_gate_type=swish，而所核对参考实现的 Attention.forward 使用 sigmoid(gate)。页面展示这个来源差异；公式按标明版本的参考实现，不能宣称已验证发布方意图。不能只凭配置字段把代码改成 swish。
10. 原 GPU 动画把 Cache 固定落在 HBM7、矩阵固定落在裸片 0。现在按资源类别在封装上方标识；不宣称真实地址、SM 分配或精确 SFU 指令。
11. 服务调度与本地执行分开。Dynamo 协调执行后端；LPU 本地编译计划安排指令、数据移动与同步。跨网的激活不应画成伴随飞来的 MXM / VXM 指令。

## 张量计算口径

27B 官方 hidden_size=5120，Flash-Next 为 2560。在“完整 D 维 FFN 输入，B=1，BF16，无填充”的假设下，张量占用分别为 10240 B 和 5120 B。这个乘法成立，但结果不是公开的线上传输字节：边界、dtype、量化尺度、批次、分片及消息封装都会影响实际流量。

27B 单层完整 SwiGLU 三个矩阵共有 3 × 5120 × 17408 = 267386880 个参数，BF16 占 534773760 B，已超过单片公开的 500 MB SRAM；不能把完整 FFN 的工作集默认画成装在一片上。假设 TP2 时每片权重占用减半，仍须预留激活、指令和通信缓冲，不能仅凭权重容量证明可部署。

Flash-Next 每个专家的 SwiGLU 参数数为 3 × 2560 × 640 = 4915200。Top-10 与共享专家合计 11 个专家参与，但真实专家编号必须来自实际 router 计算；本页不生成虚假编号或概率。权重占用也不是每轮读取字节。

## 公开连接

```mermaid
flowchart LR
    GPU["Rubin GPU"] <--> CX["CX-9"]
    CX <--> ETH["Spectrum-X Ethernet"]
    ETH <--> FE["LPX Fabric Expansion Logic"]
    FE <--> LPU["Groq LPU 集群"]
    LPU <-->|"C2C"| OTHER["其他 LPU / 托盘"]
```

这个图对应 NVIDIA 图 6 的功能连接。400 Gb/s Ethernet 与 112 Gb/s C2C 是不同层级的物理规格；均不能直接称为应用有效带宽。NVIDIA 还描述了 LPU 起草、GPU 验证的推测解码，它与本页 AFD 的 FFN 分工是不同方案，未混进同一流程。
